## <a id="sec1"></a>1. 术语与核心概念

| 口语/中文 | 学术术语 | 含义 |
|---|---|---|
| 破甲 / 解除道德限制 | **Jailbreak（越狱攻击）** | 通过精心构造的输入绕过 LLM 的对齐/安全护栏 |
| 提示词注入 | **Prompt Injection** | 在输入中注入恶意指令劫持模型行为（OWASP LLM Top 10 之首） |
| 虚拟对抗沙箱（诱导模型以为在仿真/沙箱中，"这只是模拟"从而解除约束） | 情境诱导类越狱 / role-play jailbreak | 越狱技术家族之一：构造虚拟情境让模型认为约束不适用 |
| 熔断 | **Watchdog Timer / Safety Interlock** | 独立硬件监控，超时或风险信号触发时强制进入安全状态 |
| 紧急停止 | **E-Stop（Emergency Stop）** | 机器人安全标准配置（ISO 10218 等） |
| 软硬件都写上安全 | **Defense in Depth（纵深防御）/ Swiss Cheese Model** | 多层独立防御叠加，每层有洞但对齐概率趋近零 |
| 决策层加限制 | **Runtime Enforcement / Shielding / Safety Filter** | 在策略输出与执行之间插入安全过滤层 |
| 电机电流监控 | **MCSA（Motor Current Signature Analysis）** | 用电流/扭矩信号分析设备状态（故障检测领域成熟技术） |
| 可信执行环境 | **TEE（Trusted Execution Environment）** | 处理器内的隔离执行区（ARM TrustZone 等），主 OS 被攻破也隔离 |

**核心问题陈述**：LLM/VLM 大脑的道德约束是**概率性的、可被绕过的**（越狱、注入、投毒都能"破甲"）；而被破防的具身智能造成的伤害是**物理性的、不可撤销的**。因此需要不依赖上层模型自觉的、**确定性的兜底层**。

## <a id="sec2"></a>2. 威胁模型：当 LLM 大脑被"破甲"

### 2.1 攻击已经真实发生（文献证据）

| 工作 | 要点 |
|---|---|
| **BadRobot: Jailbreaking Embodied LLM Agents in the Physical World**（[OpenReview](https://openreview.net/forum?id=ei3qCntB66)，51+ 引用） | **首个针对机器人操控的越狱攻击范式**——让具身 LLM 违反安全与伦理约束执行有害物理动作 |
| Jailbreaking Embodied LLMs via Action-Level Manipulation | 在**动作层面**（而非仅文本）绕过安全约束 |
| The Shawshank Redemption of Embodied AI（2025.11） | 系统分析 VLM 用于具身智能时的越狱漏洞 |
| 语音通道攻击（[LLM Security Database](https://llmsecurity.net)） | 带语音接口的机器人可被**语音操纵**执行有害动作——攻击面从文本扩展到音频 |
| What Breaks Embodied AI Security: LLM Vulnerabilities（[arXiv:2602.17345](https://arxiv.org/html/2602.17345), 2026.02 综述） | 把具身智能安全分为两个视角：EA 作为脆弱的"大脑"（prompt injection/jailbreak 中心）与 EA 作为物理目标 |
| OWASP [LLM01:2025 Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection) | 标准威胁分类：jailbreak 是 prompt injection 的子类 |

**攻击链总结**：文本/语音/视觉注入 → 破甲（绕过 LLM 对齐）→ 有害指令进入决策 → 机器人执行物理动作。**关键：现有对齐层（RLHF 等）在这条链的第一环就已经失效。**

### 2.2 与投毒/对抗样本的关系

三个方向攻击的是链上不同环节，互为补充（同一平台可做两类实验）：
- **对抗样本**（姊妹篇）：攻击**感知**——让模型看错（A 认成 B）
- **投毒/后门**：攻击**训练**——让模型学错
- **越狱/注入**（本篇）：攻击**认知/决策**——让模型"知道错但去做"

## <a id="sec3"></a>3. 防御全景：四层纵深防御架构

```
┌─────────────────────────────────────────────────────┐
│ L1 对齐层（LLM 内置道德约束）                        │
│    概率性防御，可被越狱/注入绕过 ← 已被证明           │
├─────────────────────────────────────────────────────┤
│ L2 决策监控层（Runtime Guardrail）                   │
│    监控 plan/意图的语义风险 → 拦截或修改计划          │
│    代表：ROBOGUARD、RoboSafe                         │
├─────────────────────────────────────────────────────┤
│ L3 控制滤波层（Safety Filter / Shield）              │
│    对动作序列做数学约束修正（QP 最小修改）            │
│    代表：Control Barrier Functions 一族              │
├─────────────────────────────────────────────────────┤
│ L4 硬件安全层（Watchdog / Interlock / E-Stop）       │
│    独立 MCU + 独立传感 + 独立电源，不可被软件覆盖     │
│    ← 本方案目标层；工业界标准成熟，AI 场景研究空白    │
└─────────────────────────────────────────────────────┘
```

对应学术理论：**Swiss Cheese Model for AI Safety by Design**（分层 runtime guardrails 的学术表达）、CISA 的 Defense in Depth 官方框架（58 页）。

## <a id="sec4"></a>4. 各层现有工作

### 4.1 L2 决策监控层（最热的软件层）

| 工作 | 要点 |
|---|---|
| **ROBOGUARD**（Safety Guardrails for LLM-Enabled Robots） | 双模块：safety reasoning module（安全推理）+ control synthesis module（控制合成），**把安全验证与计划执行解耦**——直接对口本方向 |
| **RoboSafe**（2025.12） | 用 VLM 做 runtime 安全护栏监控具身智能行为 |
| NVIDIA NeMo Guardrails | 工业界 runtime 护栏平台（输入/输出筛查） |
| Azure AI Prompt Shields | 生产级越狱模式检测 |

**共同局限**：全部是**纯软件、与被监控模型同处一个计算环境**——高权限攻击（模型被完全劫持）下监控层自身也可能被关闭/欺骗。

### 4.2 L3 控制滤波层（控制理论成熟武器库）

核心架构 "shielding / safety filter"：策略提议动作 → CBF 层解一个小 QP → **最小侵入式修正**到安全集内。

| 工作 | 要点 |
|---|---|
| [End-to-End Safe RL through Barrier Functions](https://arxiv.org/abs/1903.08792)（Cheng 2019，1100+ 引用） | 奠基：model-free RL + CBF 保证安全 |
| [Data-Driven Safety Filters](https://hybrid-robotics.berkeley.edu/publications/CSM2023_Safety_Filters.pdf)（Berkeley） | 形式化"safety filter"概念：CBF + 预测控制增强任意控制器 |
| [Safe and Efficient RL Using Safety Filters](https://arxiv.org/abs/2306.00144)（2023） | 在线修正不安全 RL 动作 |
| [CBF-RL](https://arxiv.org/abs/2510.14959)（2025）/ [CBF as Safety Instructors](https://arxiv.org/abs/2505.18858)（2025） | CBF 进训练循环（reward shaping、可微滤波） |

**关键 gap**：CBF 管的是**物理安全**（位置、速度、碰撞、关节限位），**不管语义/意图安全**（"这个动作会伤人""这是违法指令"）。物理约束可用微分方程刻画，"语义风险"目前没有对应的数学形式。

### 4.3 L4 硬件安全层（工业标准成熟，AI 场景研究空白）

| 概念 | 现状 |
|---|---|
| E-Stop 与 failsafe 链设计 | 工业界成熟：硬件 vs 软件 E-stop、链路丢失 watchdog、限速、safe stop |
| Safety PLC watchdog timer | 成熟实践：**硬件看门狗检测软件故障**，处理器失效强制 E-stop |
| **Janus**（[IEEE 2025](https://www.computer.org/csdl/journal/ec/2025/01/10508318/1Wp1XXIaRws)） | 用 MCU 的 TEE 保护机器人控制器安全——**TEE 路线已被占坑** |
| ROS 2 远程证明（Wang 2024） | TEE 为分布式机器人节点建立信任 |
| MCSA 电机电流监控 | 故障检测/预测性维护领域成熟（[ST](https://www.st.com/content/st_com/en/optimizing-motor-anomaly-detection-with-current-sensing.html)、[Edge Impulse](https://www.edgeimpulse.com/blog/brushless-dc-motor-anomaly-detection)、[能耗审计 GAN 异常检测](https://papers.phmsociety.org/index.php/phmconf/article/download/3496/phmc_23_3496)）——**但从未用于 AI 决策安全场景** |
| 安全标准体系 | ISO 10218（工业机器人）、ISO/TS 15066（协作机器人）、ISO 13849（PL 等级）、IEC 61508（SIL 等级） |

**关键 gap**：这些标准与技术为**确定性控制程序**设计。AI 大脑（概率性、可被越狱、行为不可枚举）时代的安全硬件层——风险信号如何定义、如何从语义层传导到硬件、误触发率如何评估——**没有系统研究**。

## <a id="sec5"></a>5. 创新性诚实评估（三层）

### 5.1 ❌ 已经有人做了（只能当组件，不能当主创新点）

| 技术 | 谁做的 | 教训 |
|---|---|---|
| Watchdog / E-Stop / 安全 PLC | 工业界 | 几十年成熟 |
| CBF 物理安全滤波 | Cheng 2019（1100+ 引用）一族 | 成熟，只管物理不管语义 |
| LLM 决策护栏 | ROBOGUARD / RoboSafe | 正在起势，纯软件 |
| **TEE 保护机器人控制器** | **Janus（IEEE 2025）**、ROS 2 远程证明 | **⚠️ 避坑：TEE 路线刚被占，不能当主创新** |
| MCSA 电流故障检测 | ST / Edge Impulse / 学界 | 成熟，全部用于故障检测/预测性维护 |

### 5.2 ⚠️ 新组合（可发表，需要好的 motivation）

- **电机电流侧信道 × AI 决策安全**：电流监控技术成熟，但"主控被越狱后、用物理侧信道验证执行与意图一致"这个**威胁模型没人做过**
- **TinyML × 语义风险检测**：ESP32 上跑异常检测有现成工具链（TFLite Micro、Edge Impulse、Arm 官方练习），但没人做 LLM 决策安全场景

### 5.3 ✅ 真空白（可以声称首创）

1. **语义风险的数学形式化**——CBF 框架管物理安全，"伤人/违法意图"至今没有对应的数学语言
2. **越狱攻击下的端到端硬件兜底评估**——工业安全标准面向确定性程序，"AI 大脑被破甲后硬件层拦截率"没有任何 benchmark
3. **物理侧信道的"执行-意图一致性验证"**——软件可以说谎（日志被篡改、监控被关闭），物理电流不会

## <a id="sec6"></a>6. 细化方向菜单（按硬件创新含量排序）

### D1｜物理侧信道安全验证（硬件创新 ★★★，最推荐）

- **核心思想**：主控每步向安全 MCU 提交"意图承诺"（接下来要执行的动作），安全 MCU 用**独立采样的电机电流/扭矩信号**验证实际行为与承诺一致——力超标、轨迹突变、速度异常，物理信号立刻暴露
- **杀手锏（威胁模型的哲学高度）**：假设软件层**全部沦陷**——模型被越狱、guardrail 被关闭、日志被篡改——**电流表不会说谎**。物理定律是攻击者无法网络攻击的最后一道墙
- **算法创新**：意图→预期电流模式的 forward model、执行-意图一致性评分、轻量时序异常检测
- **硬件创新**：独立电流采样链路（霍尔/分流器 → 独立 ADC → 独立 MCU），与主控物理隔离、独立供电
- **依据**：MCSA 组件全成熟、威胁模型全新——典型"新组合"创新，工程风险低

### D2｜分级熔断架构（软硬件协同，系统主线）

- 软停（暂停等确认）→ 降级（限流=限力、限速、限工作空间）→ 硬熔断（断电锁定）
- **算法**：轻量语义风险分类器；**硬件**：ESP32 安全控制器 + 继电器/限流 + 独立传感
- 创新点落在"分级策略的形式化 + 误熔断率分析"，不在单个组件

### D3｜TinyML 语义风险检测器（算法 + 部署创新）

- 把"这个动作序列危险吗"的判定蒸馏/量化到 MCU 上实时跑（ESP32-S3 有向量指令）
- 创新点在轻量化与误报-漏报权衡；与 D2 天然是同一系统的两个部件

### D4｜语义 barrier function（纯理论，高风险高回报）

- 把"伤人/违法"编码为可微约束融进 CBF 框架——做出来是 NeurIPS/CoRL 级贡献；"语义风险的数学形式"本身是开放问题，作为远期目标或主线理论章节

### D5｜TEE / 安全启动（❌ 避坑）

- Janus（IEEE 2025）已发——只能当架构组件引用，不能当贡献点

## <a id="sec7"></a>7. 推荐组合：三合一选题

**《物理不可欺骗的具身智能安全兜底层：语义风险检测与侧信道熔断》**

```
越狱攻击（BadRobot 式）
        ↓ 突破 LLM 对齐层
语义风险检测器（算法创新：蒸馏到边缘端，D3）
        ↓ 风险分级
分级熔断策略（软件创新：软停/降级/硬熔断，D2）
        ↓ 触发
ESP32 独立安全控制器 + 电流侧信道一致性验证（硬件创新，D1）
        ↓
物理断路 —— 电流不说谎，攻击者无法网络攻破
```

- **评估维度**：越狱/注入/投毒攻击下的拦截率、误熔断率（false positive）、响应延迟（ms 级，硬件层优势）
- **真机演示**：无防护机械臂执行越狱后的危险指令 vs 有兜底层时安全停止——对比视频冲击力极强
- **竞争力**：算法（检测器 + forward model）、软件（架构 + 分级策略）、硬件（独立采样 + 熔断）三层全有——**没有竞争者同时横跨这三层**（学术界做纯软件护栏，工业界做确定性程序的安全 PLC）
- **投稿**：ICRA/IROS（系统 + 真机故事）最对口；理论做深可冲 CoRL

**审稿风险与应对**：

| 风险 | 应对 |
|---|---|
| "只是焊了个板子"的质疑 | 电流侧信道的 forward model 与一致性评分算法必须做实（有模型、有消融、有指标）——硬件是让算法"不可被绕过"的载体，两者互相成就 |
| "决策出现风险"如何判定 | 语义风险检测器是算法核心，不能只写死几条 if 规则 |
| 攻击者诱导误熔断（把熔断做成 DoS） | attack-aware 评估必做：测误触发攻击下的任务完成率 |
| 与工业安全 PLC 的区别 | motivation 明确写：面向概率性 AI 大脑（行为不可枚举），非确定性程序 |

## <a id="sec8"></a>8. 实施路线与技术栈

| 模块 | 技术选型 |
|---|---|
| 机械臂平台 | 实验室机械臂（与对抗样本方向共用） |
| 大脑 | 开源 VLM/LLM（Qwen-VL / LLaVA 类，或 OpenVLA 的语言层） |
| 攻击注入 | BadRobot 式越狱 prompt、prompt injection 样本、（可选）对抗补丁 |
| 语义风险检测器 | 小模型（蒸馏/量化到边缘端）；YOLO 检测人体接近作为物理风险信号之一 |
| 硬件安全层 | **ESP32 / STM32**：独立看门狗 + 继电器/电机使能控制 + 独立传感（电流、接近、急停按钮） |
| 电流侧信道 | 霍尔传感器（ACS712 类）或分流器 + 独立 ADC 采样；与主控物理隔离 |
| 通信隔离 | 安全层与主控单向通信（主控→安全层心跳+意图承诺，安全层→执行器断路），安全层不暴露网络接口 |
| 评估指标 | 攻击拦截率、误熔断率、响应延迟（ms）、任务成功率损失 |
| 安全标准参考 | ISO 13849 的 PL 等级方法论（设计论证章节引用，不必认证） |

**节奏建议**：

| 阶段 | 任务 | 产出 |
|---|---|---|
| 第 1 月 | 复现 BadRobot 式越狱（证明威胁在本平台真实存在） | motivation 实验 |
| 第 2–3 月 | 搭硬件安全层原型（ESP32 看门狗 + 电流采样 + 断路）+ 规则版风险检测 | 兜底层 demo |
| 第 4–6 月 | 语义风险检测器训练 + forward model + 分级熔断策略 + 端到端攻防评测 | 论文主体 |
| 真机演示 | 越狱攻击下：无防护 vs 有兜底层 对比视频 | 差异化卖点 |
