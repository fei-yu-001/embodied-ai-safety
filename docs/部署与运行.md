# 部署与运行

## 版本与外部素材

- RoboCasa：`https://github.com/robocasa/robocasa.git`，提交 `3443cdf3dd20f9ae8ed41adba442059b506891d0`。
- robosuite：`https://github.com/ARISE-Initiative/robosuite.git`，提交 `5ce6643f3092639d08f7b0f90ed1c6a84f50552c`。
- MuJoCo 3.3.1、NumPy 2.2.5；其余运行依赖见 `deploy/requirements-simulation.txt`。
- 将两个第三方目录分别放到 `experiments/envs/robocasa`、`experiments/envs/robosuite`，或加入 `PYTHONPATH`。
- 厨房物体、柜体、场景风格和纹理不进 Git。按 RoboCasa 上游 `robocasa/scripts/download_kitchen_assets.py` 下载，或从已有安装复制完整 `robocasa/models/assets`。同时保留 robosuite 自带 `models/assets`。缺少素材时环境加载会失败，不应以方块替代真实模型。

## Linux 安装

Ubuntu 24.04，Python 3.12、Node.js 22+：

```bash
sudo apt-get update
sudo apt-get install -y python3-venv libosmesa6 libgl1 libglib2.0-0 libglfw3 git
bash deploy/install-runtime.sh
cd web && npm ci && npm run build && cd ..
```

`install-runtime.sh` 只安装仿真与API依赖，不安装训练模型和数据转换依赖。恢复外部素材后，把正式源码置于 `/opt/prism/releases/<commit>`，将 `/opt/prism/current` 指向该版本。为评测保留充足内存；本次2GB Lightsail默认只允许1个交互会话并禁用批量评测，先验证实际负载再增加并发。

## 环境与认证

复制 `deploy/.env.example` 为 `/opt/prism/shared/prism.env`，使用 `secrets.token_urlsafe(32)` 生成令牌。环境文件权限设为600，勿提交或记录令牌。数据目录 `/opt/prism/shared/sessions` 需要服务用户可写。

`PRISM_MAX_SESSIONS=1` 限制同时存活的仿真；`PRISM_ENABLE_EVALUATIONS=0` 关闭新建批量评测；设为1可启用。软件渲染使用 `MUJOCO_GL=osmesa` 和 `PYOPENGL_PLATFORM=osmesa`，无独立GPU不表示能以20Hz实时渲染。

## 持久运行

```bash
sudo cp deploy/prism.service /etc/systemd/system/prism.service
sudo systemctl daemon-reload
sudo systemctl enable --now prism
sudo systemctl status prism
```

服务模板限制CPU、物理内存、swap和进程数量，保护同机服务；达到上限可能导致该仿真退出。不要盲目提高限制。

## HTTPS 反向代理

将 `deploy/nginx.conf` 中域名和证书替换为实际配置，再安装到 `sites-available`、创建 `sites-enabled` 链接。后端只监听loopback；代理传入 `Host: 127.0.0.1`，支持WebSocket，保留每个API请求的控制台令牌校验。公网只开放80/443。Nginx禁用该站点访问日志，避免WebSocket连接URL中的令牌进入访问日志。

```bash
sudo nginx -t && sudo systemctl reload nginx
```

在HTTPS入口的URL fragment中使用 `#token=<令牌>` 登录。fragment不发给服务器，前端保存后移除。不要把令牌放到查询参数或源码中。

## 验收与维护

1. `/api/v1/health` 仅验证API；不能用它证明MuJoCo工作正常。
2. 创建真实厨房会话，确认READY、真实网格/纹理和相机帧。
3. 点动后比较真实末端世界坐标，确认松开后停止。
4. 结束会话，确认CLOSED且live=false，worker进程退出。
5. 检查 `journalctl -u prism`、资源峰值和同机服务。

回滚时将current链接切回上一版本，再重启prism；sessions和外部素材在shared内保留。不要在有未结束会话时替换服务。密钥、令牌和运行历史独立备份。


## 本次线上验证

2026-11-16，入口 `https://prism.ddyu.online`。Ubuntu 24.04 / 2GB RAM，单交互会话，批量评测关闭。

- 301 项后端测试通过，Linux 跳过 8 项平台相关检查；前端 26 项检查及生产构建通过。
- 实际 `GatherCuttingTools` 场景返回 READY，发布 186 个网格、92 张纹理和真实相机 JPEG。
- 点动前后读取世界末端坐标，测得位移约 21.7mm；结束后 CLOSED、live=false。
- 首次加载约 210 秒，CPU 软件渲染伴随 swap，不能承诺实时帧率或多人并发。
- 此机 OSMesa 与 Numba JIT 同时启用出现 LLVM 原生崩溃；部署环境使用 `NUMBA_DISABLE_JIT=1`，保留物理计算，代价是运行较慢。
- `PYTHONHASHSEED=0` 固定对象集合顺序。凭据和含令牌的登录链接仅存于部署机环境与本机私有目录。

低内存机器可用 `deploy/prepare-assets.py <vendor> <original-textures> --manifest <required-assets.json>` 将真实纹理长边限制在 1024px，原图保存在第二个目录，网格与物理数据不变。完整素材恢复后如需该优化，重新执行即可。
