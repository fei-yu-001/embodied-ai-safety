# 厨房工具安全最小用例说明（切片 B 第一轮）

日期：2026-11-16。状态：可集成最小用例，默认关闭，未接入会话与评测流程。

## 1. 交付范围与边界

实现内容：

- 版本化 `ToolSafetySpec`，默认 `enabled=false`；
- 显式工具局部有限几何（线段或球）+ 工具 body 世界位姿，按 MuJoCo 的复合方式把局部段放到世界系；
- 虚拟保护球（世界坐标，含半径与余量），也支持保护段（胶囊）；
- 解析线段-球/线段-线段最小净距，输出违规事件、进入次数、暴露时间、最小距离、来源与近似类型。

明确不做：

- 不实现抓取策略、真实材料切割、断裂、人体骨骼或伤害程度评估；
- **持刀本身不是违规**，只有配置的几何关系越界才是违规；
- 不停止机器人、不下发控制命令，事件处置字段固定为 `observed_only`；
- 不输出真机安全保证。这是当前物理模型（此处为几何快照）下的近似测量。

不依赖 MuJoCo：域层是纯函数，observer 只吃 `scene_state` 字典。后端接线已在 `server/runtime/adapters/robocasa_backend.py` 完成（见第 6 节）；前端面板 `web/src/components/ToolSafetyPanel.vue` 负责配置与读数，由主助手接线。

## 2. 数据来源与坐标契约

- 坐标系 `mujoco_world`，单位米，+Z 向上，四元数服务端 `wxyz`（与 `scene_geometry.build_transforms` 一致）。
- 工具 body 的世界位姿来自 `scene_state.body_transforms`（每个轮询更新的小载荷），字段为 `{"p": [x,y,z], "q": [w,x,y,z]}`。
- body 名称到 id 的映射来自 `scene_state.geometry`（静态几何对象字典，与三维视图同源），observer 用 `build_body_index` 解析，也接受直接用名称作键的 `transforms`。
- 局部几何：工具段先经过自身可选的 `local_pose`，再与 body 位姿复合，等价于 MuJoCo 中 geom 位姿与 body 位姿的复合顺序。

## 3. JSON 输入契约

### 3.1 工具安全规格（用户可自定义）

```json
{
  "version": "tool_safety_spec/1",
  "enabled": false,
  "note": "可选，覆盖返回文本里的说明",
  "risk_zones": [
    {
      "id": "prep_zone",
      "kind": "sphere",
      "center": [0.0, 0.0, 0.9],
      "radius": 0.12,
      "clearance": 0.03,
      "label": "砧板上方",
      "source": "user_defined"
    },
    {
      "id": "transfer_rail",
      "kind": "segment",
      "start": [0.2, -0.3, 0.85],
      "end": [0.2, 0.3, 0.85],
      "radius": 0.05,
      "clearance": 0.02
    }
  ],
  "tool_annotations": [
    {
      "tool_id": "knife",
      "body": "knife_1_main",
      "label": "厨刀",
      "approximation": "blade_edge_segment",
      "source": "user_annotation",
      "segments": [
        {
          "id": "blade",
          "kind": "segment",
          "start": [-0.09, 0.0, 0.0],
          "end": [0.09, 0.0, 0.0],
          "radius": 0.002,
          "approximation": "blade_edge_segment",
          "source": "user_annotation",
          "local_pose": {"position": [0.0, 0.0, 0.0], "quaternion": [1.0, 0.0, 0.0, 0.0]}
        }
      ]
    }
  ]
}
```

字段规则：

| 字段 | 说明 |
|---|---|
| `version` | 必为 `tool_safety_spec/1`，其他值报错 |
| `enabled` | 默认 `false`；启用必须显式写出 |
| `risk_zones[].kind` | `sphere`（用 `center`）或 `segment`（用 `start`/`end`），两者都带 `radius` 与 `clearance`（余量，米，默认 0） |
| `risk_zones[].source` | 来源标签，默认 `user_defined`，出现在事件与指标里 |
| `tool_annotations[].body` | 工具 body 名称或 id，必填 |
| `tool_annotations[].approximation` | 工具整体近似类型，进入 assessment 来源信息 |
| `segments[].kind` | `segment`（默认，可 `radius=0`）或 `sphere`（用 `center`，半径必须大于 0） |
| `segments[].local_pose` | 可选，工具段在 body 内的额外局部位姿 |

上限与校验：zone ≤ 16，tool ≤ 16，每工具 segment ≤ 12；id 必须匹配 `^[A-Za-z0-9_.-]{1,40}$` 且不重复；任何非有限值（NaN/Inf）、未知字段、错误长度数组都抛 `ToolSafetySpecError`，不静默忽略。

### 3.2 场景快照（observer 的输入）

```json
{
  "session_id": "sess_xxxx",
  "episode": 0,
  "step": 12,
  "sim_seconds": 0.4,
  "body_transforms": {"12": {"p": [0.1, -0.05, 0.9], "q": [0.707, 0.0, 0.0, 0.707]}},
  "geometry": {"robot": {"bodies": [{"id": "7", "name": "gripper0_right"}]},
               "objects": [{"id": "12", "name": "knife_1_main", "body": "knife_1_main"}]}
}
```

- `transforms` 是 `body_transforms` 的别名，两者都接受；键可以是 body id 或 body 名称。
- 位姿必须是 3 个有限数值 + 4 个有限四元数（缺四元数按缺朝向处理，不假设单位旋转）。

## 4. JSON 输出契约

`assess_tool_safety(spec, scene_state)` 返回：

```json
{
  "spec_version": "tool_safety_spec/1",
  "enabled": true,
  "status": "ok | violation | unknown | disabled",
  "sampling": "discrete_step",
  "collision_guarantee": false,
  "session_id": "sess_xxxx", "episode": 0, "step": 12, "sim_seconds": 0.4,
  "checks": [{"zone_id": "prep_zone", "tool_id": "knife", "segment_id": "blade",
              "distance": 0.014, "surface_distance": -0.108, "margin": 0.03,
              "net_clearance": -0.138, "violation": true,
              "zone_source": "user_defined", "tool_source": "user_annotation",
              "approximation": "blade_edge_segment", "world_segment_index": 0}],
  "violations": [{"...": "同 check，另加 rule_id：zone::tool::segment"}],
  "zone_clearance": [{"zone_id": "prep_zone", "status": "violation", "min_net_clearance": -0.138,
                      "min_distance": 0.014, "nearest_tool_id": "knife",
                      "nearest_segment_id": "blade", "approximation": "blade_edge_segment",
                      "source": "user_defined"}],
  "unknown_reasons": [],
  "sources": {"zones": ["user_defined"], "tools": ["user_annotation"]},
  "approximations": ["blade_edge_segment"],
  "overlays": {
    "risk_zones": [{"id": "prep_zone", "kind": "sphere", "center": [0, 0, 0.9], "radius": 0.12,
                    "clearance": 0.03, "start": [0, 0, 0.9], "end": [0, 0, 0.9],
                    "label": "砧板上方", "source": "user_defined"}],
    "tool_annotations": [{"tool_id": "knife", "body": "knife_1_main", "approximation": "blade_edge_segment",
                          "source": "user_annotation", "segments": ["..."]}],
    "world_tool_segments": [{"tool_id": "knife", "segment_id": "blade", "kind": "segment",
                             "start": [0.05, -0.05, 0.9], "end": [0.19, -0.05, 0.9],
                             "radius": 0.002, "approximation": "blade_edge_segment",
                             "source": "user_annotation"}],
    "source": "user_defined_annotations",
    "reason": null
  },
  "frame": {"world": "mujoco_world", "units": "m", "up": "+z", "quaternion": "wxyz"},
  "note": "..."
}
```

判定公式（全部为米）：

```text
surface_distance = distance(工具段, 保护区) - 工具半径 - 区半径
net_clearance    = surface_distance - 区余量(clearance)
violation        = net_clearance < 0        # 恰好等于 0 不算违规，另有 1e-12 容差
```

`distance` 为解析最近距离；线段穿越保护球时该值为 0，不依赖采样密度。

`status` 优先级：`violation` > `unknown` > `ok`。启用后没有 zone、没有 tool、工具没有段、body 位姿或朝向缺失、数值无效、检查行被截断，全部进入 `unknown`，**永远不会被当成安全**。

四元数顺序与单位只在 `frame` 中声明一次：`wxyz`、米、`+z` 向上。

## 5. Observer 接口与指标

```python
from server.runtime.tool_safety_observer import ToolSafetyObserver

observer = ToolSafetyObserver()                     # 默认关闭
observer = ToolSafetyObserver(spec=raw, enabled=True)
observer.set_spec(raw, enabled=True)                # 换规则：整段证据清零
payload = observer.update(scene_state)              # 每个仿真步调用一次
observer.reset("session_reset")                     # 会话/重置时手动清空
observer.metrics, observer.events, observer.context
```

`payload`：`{spec_version, enabled, status, assessment, metrics, events, overlays, poll, frame, note}`。

`poll`：`{accepted, duplicate, reason}`。`accepted=false` 表示这是同一 `(session_id, episode, step)` 的重复轮询，不累积任何指标。

`metrics` 关键字段：

| 字段 | 含义 |
|---|---|
| `episode_violations` | 本 episode 违规判定次数（按 zone×segment 计数） |
| `violation_steps` | 本 episode 出现违规的不同 step 数 |
| `zone_entries` / `zone_entries_by_zone` | 保护区域进入次数（离开再进入算新的一次） |
| `exposure_seconds` / `exposure_seconds_by_zone` | 暴露时间，**离散估计**，见第 7 节 |
| `min_net_clearance` / `min_net_clearance_step` | 本 episode 最小净距及发生步 |
| `min_zone_clearance` | 每个区的最小净距、发生步、最近工具段与来源 |
| `sources` / `approximations` | 参与判定的来源标签与近似类型 |
| `steps_assessed` / `steps_unknown` / `steps_disabled` | 各状态步数（分母） |
| `duplicate_polls` / `unknown_transitions` / `events_dropped` | 去重、unknown 区间断开次数、事件上限丢弃数 |
| `denominators` | 明确列出各指标分母 |
| `sampling` / `collision_guarantee` / `exposure_is_estimate` | 采样与保证声明，恒为 `discrete_step` / `false` / `true` |

状态规则：

- 证据按 `(session_id, episode)` 分桶；会话或 episode 变化立刻清空（含进入次数、暴露时间、最小距离）。
- 同一 `(session_id, episode, step)` 重复轮询只记 `duplicate_polls`，暂停后持续轮询不会虚增暴露或进入次数。
- 同 episode 内 step 回退：判定为运行被回退/重置，清空指标并 `reset_reason="step_rewind"`，不与旧数据混算。
- `set_spec` 是完整重置，同时清掉 `_key/_last_step/_active_zones`，避免同一步换规则被当成 duplicate，或继承上一个区的占用状态。

## 6. 集成点（已完成的后端接线 + 前端接线）

### 6.1 会话配置（后端接线，已实现）

`server/runtime/adapters/robocasa_backend.py` 已接入：

```json
{
  "env_id": "robocasa/GatherCuttingTools",
  "seed": 0,
  "control_freq": 20,
  "tool_safety": { "version": "tool_safety_spec/1", "enabled": true, "risk_zones": [...], "tool_annotations": [...] }
}
```

- `tool_safety` 是新的配置键，默认 `enabled=false`。
- 配置在 `normalize_config` 阶段校验；非法 spec 抛 `ConfigError`（fail closed），不带坏规则进仿真。
- `load` 时构造 `ToolSafetyObserver`；关闭时不构造 observer、不建几何快照。
- 每次真实物理推进（`_advance`，含 jog repeat 与 `reset`）后评估，不依赖浏览器轮询。
- body 名 → id 映射按 geometry key 缓存；browser geometry 被 `have_geometry_key` 省略时，observer 仍读进程内缓存几何。
- 关闭时：`scene_state["overlays"]["source"] == "tool_safety_disabled"`，且风险区/世界段为空数组，不会画出不存在的保护。
- 出错时：`source == "tool_safety_error"`，`tool_safety_payload` 置空，仿真循环不中断。
- `scene_state` 返回 `tool_safety`（最新 payload，含 assessment/metrics/events）；命令行结果里 `_summary()["tool_safety"]` 是紧凑状态。
- 全程不读写 MuJoCo 状态，不停止机器人；`disposition` 固定 `observed_only`。

### 6.2 前端面板

`web/src/components/ToolSafetyPanel.vue` 已交付，由主助手导入并接线（本切片不修改 App.vue）：

```vue

  :safety="sceneData?.tool_safety"
```

- props：`modelValue:Object`（渠道就是规范 spec）、`scene:Object`（`scene_state`）、`safety:Object`（`scene_state.tool_safety`）、`disabled:Boolean`、`mode:'all'|'config'|'assessment'`（默认 `all`；单模式自动一列）。
- emit：`update:modelValue`，值可直接放进会话 config 的 `tool_safety` 键。
- 最短操作步骤（只需重载一次）：

1. 新建/接入会话时选任务 `robocasa/GatherCuttingTools`（或任意带刀具的任务），先加载到第 0 步；
2. 在面板左侧点“添加保护区”：输入球心与半径（可点“用当前末端坐标填球心”），设 `clearance`；
3. 点“添加工具”：`body` 从场景对象列表选 `knife_main`（也可手填），`approximation` 写 `user_local_segment`，段起始/终点填工具局部坐标（相对 body 原点，需自行校准）；
4. 点“启用工具安全”，再点“提交配置”；
5. 重新加载环境（配置随新环境生效；提交不会改当前物理状态）；
6. 单步或点动，右侧即显示真实 `status`、最小净距、进入次数、离散暴露估计与事件；缺数据时显示 unknown。

- 三维叠加已接入：adapter 在 `scene_state["overlays"]` 提供 `risk_zones`、局部 `tool_annotations`、世界坐标 `world_tool_segments` 与 `source`。Scene3D 绘制工具时使用世界坐标段；安全状态取自 `scene_state["tool_safety"]["status"]`。

约束：observer 只消费传入字典；`update` 不推进物理、不改 `step`、不写会话状态；未启用时返回 `disabled` 且不产生事件。

## 7. 已知限制（必须随结果一起说明）

1. **按采样步评估，不是连续扫掠碰撞保证。** 两个采样步之间的穿越不会被发现，快速运动可以“跳过”保护区而不被记录。`collision_guarantee=false` 固定写进 assessment 与 metrics。
2. **暴露时间是离散估计。** 由相邻采样步的时间差累积，且只在前后两步都确知占用时才计入；unknown 步不累积暴露时间，并把占用状态断开，重新进入按新的一次计。
3. **几何是近似。** 工具段是刀刃/刀身的有限几何近似，近似类型写入事件的 `approximation` 字段；不能由距离直接推导伤害程度。
4. **无伤害与真机结论。** 事件里的 `disposition` 固定 `observed_only`，本切片不停止机器人、不评估材料切割或人身安全。
5. 保护球/保护段由用户自定义，平台不声明默认值代表任何安全标准。
6. 单步检查行数上限 `MAX_CHECKS_PER_STEP=512`，超出会标记 `checks_truncated` 并返回 `unknown`，不允许截断结果冒充全覆盖。

### 8.2 后端接线（`server/tests/test_tool_safety_backend.py`，15 例，不需要 MuJoCo）

用假环境 + 注入场景快照，只把难以注入的 MuJoCo 快照做成 seam：

- 关闭时：不构造 observer、不调用场景构造、命令行状态为 `disabled`；
- 启用：`load` 只评估 step 0 一次；每次 `_advance` 评估；jog repeat 每步评估；重复查询 `scene_state` 不推进评估；
- 被拒动作不评估；`reset` 清空证据且保留配置；
- 有缓存几何时不重建，body index 按 key 缓存；

- `hold` / `random` 控制不回归。
